# 直播权限边界与待验收项

2026-10-31。本文描述本分支新增源码；尚未构建、部署或验证拦截效果，当前已安装客户端仍是旧产物。防护是否生效需要单独验收，不能由源码存在推断。

## 信任来源与执行

主人操作来自 DSH 认证管理连接。已静态核对本机 DSH0.2.1-rc.3 的 `dsh-client-connection`：`connection.fetch.register()` 的 exact route 在派发前要求 `peer.principal.kind === 'owner'`；HTTP carrier 先验证认证凭据及 Host/Origin。所有本插件管理路由都注册在这个接口下，另用进程级随机请求头约束修改意图；该请求头本身不是独立身份认证。内部 Request URL 可能为 `dsh.internal`，不拿它与浏览器真实 Origin 作错误比较。

舞台服务器独立监听，观看令牌只用于舞台。管理请求头、私密记忆及待审操作不通过舞台服务发布。不要把 DSH 主人认证凭据分发给观众；拥有宿主管理身份的客户端本来就具有主人权限，本插件无法将其当作普通观众限制。

公屏弹幕、礼物、SC、主播/管理员账号的公屏发言、主页、视频字幕、游戏文本、旧记忆和模型写下的“已批准”都不是授权。主播账号的公屏消息已不再进入高优先级 owner 队列。原每90秒将新私信摘要自动推给直播模型的后台路径已从源码删除；私信查询工具默认拒绝。

在实际工具注册表上注册单向拒绝 `tools.guard`。按真实执行会话、实际工具与参数检查；未知工具默认拒绝，不能用提示词、参数里的角色声明、子会话或 PTC `run_code` 绕过。原生 registry 为同一次执行提供同一个 token，全局/继承 guard 只消耗一次批准。

受保护会话写入 `$DSH_HOME/dsh-livestream/access/protected-sessions.json`；结束直播不抹掉旧上下文的外部来源。根 guard 配合实际 agent context 的 scoped guard、持久 parentSession 和 currentInitiator 继承，未知后代只获得最小主播权限。保护记录损坏时失败关闭，不能覆盖坏记录后自动放权。

会话自身的scoped guard随实际agent context释放，不在停用宿主插件时主动拆除；存活旧会话会因权限服务未就绪而拒绝工具。宿主和插件的热替换、跨配置复制/导出会话等仍需单独验收；本插件不是在用户卸载全部防护、改源码或另起进程后仍然生效的操作系统隔离。

## 权限分层

| 角色/入口 | 可做 | 约束 |
| --- | --- | --- |
| 主人管理界面 | 设置、开播、人设/私密记忆、审核/撤销 | 宿主认证主人连接；修改还需进程请求头 |
| 直播评论线 | 公开主页/视频/评论、画面/统计、游戏状态、提交游戏建议 | 建议排队，不直接把模型消息当作主人命令 |
| 游戏线 | 固定天数任务、观察、模型计划与笔记、明确批准的基础动作/农活 | 本版直播预算一天；重复启动不重领预算；农活可用主人有限范围授权；不开放开发权限 |
| 敏感账号动作 | 私信发送、评论/动态、点赞/关注/收藏/投币、禁言/解禁、改标题等 | 具体操作和参数需主人限时批准一次 |
| 敏感游戏动作 | 泛化交互/用工具、购买/制作/丢弃/容器转移、原生UI/输入/战斗、原始钓鱼/渔具及恢复 | 具体会话、工具、完整参数限时批准一次；明确语义流程可按下述有限范围授权，未知流程仍拒绝 |
| 人物记忆工具 | 受限公开检索、待审提议/摘要 | 后端绑定人物和实际主体，不接受自报主人/农场身份；不改核心人设 |
| 文件/shell/安装/开发及未知工具 | 不开放给受保护直播会话 | 接入开发仍用独立、可信主人发起的开发会话 |

基础动作允许列表可读于 `packages/dsh-livestream/src/core/access.ts`；只认明确工具名，不按前缀自动放行。容器转移可能产生出货等后果，因此需要审核。泛化原生输入仍是原子能力，并不因此变成完整、安全的业务流程。

后续动物照料、守恒分拆、机器投料/收取和相应`animal_care`/`machine_cycle`/`machine_stop_tracking`均加入具体操作审核范围，未默认为观众自治权限。只读`production`和`game_recovery`不重领预算，后者只看实际会话自己的记录。机器原料堆叠/额外材料限额与漏斗权限分别绑定；允许漏斗意味着允许原生机制继续消费其中物料，不把它混入玩家背包预算承诺。续接jobId不能修改原预算或漏斗选项。

### 主人的有限经营范围授权（新增源码，未验收）

主人可在控制台对当前游戏线的一条有效待审农活，选择“授予此范围”：1–128次流程调用、1–1440分钟内可开始。不是授权整个游戏，也不是给某位观众权限。授权绑定真实执行会话、当前runId、存档saveId和程序集MVID；这些由游戏宿主读取，不能在模型参数中自报。

- `plant`：固定种子ID、明确的最多8格和浇水选择；允许使用地块子集，不能换种子、加地块或改变浇水约束。累计种子预留上限为地块数×调用次数。
- `animal_care`：固定地点、最多8个真实动物ID及pet/harvest动作；允许子集，不包含购买、出售、迁移、繁殖或饲喂。
- `animal_feed_prepare`：固定最多8个饲料槽与干草品质；每空槽最多消耗1份实际背包干草，累计预留上限为槽数×调用次数。已填草槽跳过，不取筒仓、不改饱食度、不调用自动喂食；填槽不等于已吃饱。
- `ground_collect`：固定最多8个地面位置、物品ID、原始品质及单件源；允许目标子集，不加目标或换品质。仅普通spawned/grabbable、非任务/机器、匹配动物产物目录或原生forage的物品。原生采集品质与Gatherer奖励以实际入袋收据核对，不把目录匹配冒充具体生产动物。
- `machine_cycle`：固定机器位置/物品ID，原料ID/品质及每次堆叠上限、逐项额外材料预算；缩减预算可用，不得增加。累计保守预留为每次各上限×调用次数。原料省略的范围只能接手已有一轮；含原料范围的续接从持久jobId记录解析原预算后匹配，不把UUID本身当作权限。漏斗自动补料不能用此范围授权，仍需逐次审核。
- `fishing_cast`：固定站位、方向、钓竿槽/物品、完整饵/逐槽鱼钩ID与品质、抛竿力度和宝箱选择；单次时长/饵消耗/各槽磨损允许缩减。累计保守预留为单次耗材/磨损上限×调用次数。耗尽可空装继续，不能换另一种/品质耗材或增加原来空槽附件。原始`dsh_fish`与渔具装卸仍逐次审核，不能借原始控制器绕过范围。

每次匹配先原子写入剩余额度，再放行；多层guard仍只扣一次。失败、跳过、处理中等待、收取续接都各占一次，不自动退款或重领。范围不增加经营天数及日动作预算。开始期限只限制新流程启动，已经保留额度的有限流程可继续；撤销任一范围会同时取消当前游戏连接，阻止后续内部步骤，已发生效果不回滚。原始工具输入、账号动作、未知流程和恢复接管不能借用农活范围。

`farm-grants.json`保留最多32项有效授权及有限历史；重启读取原剩余额度，记录损坏或保存失败则拒绝放行。游戏线新增只读`game_permissions`查看自身范围，不接受其他会话ID，不具备授予或撤销能力。控制台“批准一次”和“范围授权”都不会自动执行待审请求；AI需再次请求已获准操作。

待审操作绑定会话ID、工具名及完整参数哈希，最多32项，待审120秒；批准后60秒内相同参数只可执行一次，批准不会自动重放。游戏建议最多32项，主人传给游戏线仅代表选中建议，后续敏感工具仍单独审核。游戏线离线时保留该建议。

“锁住直播工具并停止控制”会清空批准、持久冻结旧会话并中止当前星露谷连接。冻结会话不能自行解冻或复用；应新建干净会话。正在远端执行的动作可能已经产生效果，停止不是回滚。审计只存会话/工具/参数哈希和决定，避免复制私信与凭据。

### 普通社交的具体审核（新增源码，未验收）

`npc_talk/gift/deliver/dialogue`及原始`dsh_npc_action/dsh_dialogue`加入明确的逐次审核目录，没有自动继承农活范围。查询NPC/任务/当前对话可读；模型或观众自报“已批准”“主人说过”不产生权限。答案请求包含真实说话人、语义revision、问题全文、可见选项key与全文；原生再次匹配，旧问题批准不能套用到新问题。

普通对话自动揭示/推进拒绝问题及剧情事件，不默认选答案；赠礼限1份明确普通物品，任务交付只按实际ItemDeliveryQuest的数量，过大堆叠先守恒分拆。即时效果与对话结束分开；`waiting`续读不重新递物。自动推进出现未批准金币/物品消耗、或独立背包与关系/任务账本不符时停止接管，不重放。这仍需实际对抗与游戏验收；社交可复用范围、选择结果的专门金币/材料预算尚未实现。

### 任务接取与金币领奖（新增源码，未验收）

`quest_accept_daily`、`special_order_accept`和`quest_claim_money`以及原始`dsh_quest_ui`均保留具体会话/完整参数的一次限时审核，未加入可复用经营范围。接受订单会锁定同类型另一选择，参数必须绑定当前原生候选key和合同指纹；观众贴来的任务文本、空ID或“已批准”不作为授权。普通任务key绑定当前实际对象，存档重载后的旧key不匹配新实例。

金币领奖绑定实际目标和准确正数金额；原生奖励点击、奖励清空/领取参与者变化和独立MCP余额/全部背包核对，未知即停止且不重领。正常开日志、翻页/选择、原生返回清理和关闭也占原日动作预算并经过pending检查点；不直接调用Grant、改金币/完成标记，不取消别的任务。已确认接取/领奖的收据与之后的界面清理分开，不能因清理失败重放经济动作。当前只覆盖明确子流程，完整订单/非金币奖励、金币支出范围和对抗验收仍待做。

### 后端经历与记忆补送（新增源码，未验收）

游戏`experiences`只读本存档已核对步骤，不提供任意事实写入。离线`game_history`由宿主从实际执行会话的持久接管记录定位原存档，不接受模型自报其他身份；`recoverDays`只补记已经完整确认的日报，且须先停止本进程控制连接，不能重放睡眠或重领预算。

人物记忆的后端写入不注册为模型工具或HTTP管理动作；模型依旧只能提议记忆。目标人物只读实际游戏Session已持久绑定的人物，缺失绑定不取全局默认补归属；待送不随切换重定向。eventId/内容摘要/记忆ID事务去重，遗忘或纠正后不因重试重新建立；主体退出同样生效。公开事实摘要不含观众聊天、主人私密记录、原始对话或旧UI引用，也不进入核心system设定。历史里的旧承诺和“已接受任务”均不产生工具授权。

人物会话固定ID和核心历史版本，检索/提议/压缩/公开上下文沿用绑定；主人管理界面查看绑定，没有模型重绑接口。公开限制持久保留，配置改回assistant不能降级；私密会话或私密父会话不能转换为直播会话，不能靠新标记擦除旧上下文。旧的无绑定历史、带历史fork迁移、父关系冲突或缺失均拒绝猜归属。直播开播/续播核对人物两线的固定ID/版本，切默认人物不会改变在播名字或记忆归属。这些都是新增源码，未构建部署或隐私/继承/重启验收。

人物库遗忘不会删除独立游戏经历账本；该账本尚无独立图形化遗忘入口。跨进程协作、重启隔离、坏文件、私密范围与补送/遗忘竞争等实际验收仍待完成。

### 明确食物范围（新增源码，未验收）

主人可从实际待审`consume_food`建立有限范围：只限一个食物ID和原始品质、每次最多1份，次数/启动期限/真实会话与runId/saveId/MVID沿用经营范围规则。负食用值默认禁止，明确允许也不能自动提高原生命/体力损失核对预算、动画期限或累计份数；模型只能缩小范围。原始`dsh_consume`保留具体审核，不借范围执行通用物品使用、药书/图腾、购买、丢弃或输入。

每次先持久扣调用额度，原生拒绝、过期或未知结果不退款。低资源补给只放开原收尾条件对这一个食用操作的限制，仍须活着、原生空闲、2600前且有当日剩余额度；不重领预算或绕过禁食/恶心/饱食/饮水/姿态条件。原生可能替换食物/饮料Buff，上限只作事前预留与事后核对，不回滚意外结果；未知即停止，不自动加吃一份。新查询与已核对食用经历均为数据，不给观众或记忆授权。全部尚未实机验收。

### 原生制作/烹饪的具体权限（新增源码，未验收）

`craft_recipe`及原始`dsh_craft`保留具体主人审核，没有可复用制作范围。明确模式、实际配方key、1–25次、入口/工作站位置、是否关闭页面；`materialBudget`按player/containers来源组、完整ID、品质及整批累计上限约束。containers代表该原生页面实际连接并锁定的材料来源，集合建立后不可扩张，不表示能读写任意箱子或跨地图仓库。齐氏调味料另需明确允许和实际来源预算，不能用关闭原生规则规避消耗。

每次取料前比较最新计划及预算，Native再次校验当前revision、真实配方/来源及单次预算；原生右键固定只做一次。未知/超时/取消不重做，已确认产物仍在游标上时不能再制造一份。入袋和关闭可在收尾条件下使用原日剩余动作，批次开始/定位后会预留这些动作，不退款或重领额度。只读查询不生成随机产物，后端已确认经历不包含旧可执行Ref，也不产生授权。

全部为新增源码；没有创建实际批准、制作物品、编译测试或部署。真实UI/资源/锁/停止/重启和对抗验收仍pending。

### 普通储物的具体权限（新增源码，未验收）

`storage_transfer`及原始`dsh_storage_ui/stardew_transfer_inventory_item`均保留具体会话、完整参数的一次限时审核，没有新增可复用储物范围。批次参数固定真实箱子实例key、位置/类型/物品、入口/关闭选择、1–16步方向/源槽/ID/品质/数量和可选空槽目标；额外Ref约束不能在执行时替换。工具默认拒绝，需明确允许、实际MCP物品Ref与等级，不能借腾包存走其他工具、擅自换箱、交换、丢弃或出货。小冰箱、共享/祝尼魔/漏斗/出货箱/自定义容器与全仓规划不在此范围。

Native实例key/digest与MCP Ref/revision分别绑定各自实际来源；旧记忆、外观同名或观众提供的引用不能替代新查询。逐步核对双库存、准确源槽剩余、对称数量变化、Native数量和金币，失败若不能独立证明两侧未变则停止接管；不靠“已回滚”的文本放行，不重放或追加补偿。已确认移动和界面清理分开，后端经历只记移动，不算新收益或授权。有限批次预留原日动作；收尾条件只开放当前已打开菜单的有限存取/关闭，不允许新开箱，不重领预算。

查询完整库存时，协议省略的空槽item只在完整显式索引/容量/版本确认后规范为null，不能把截断当空。扩展背包和可见菜单容量不一致、总格数超MCP的128完整投影上限均拒绝。未编译测试、安装、创建实际批准/经历或转移物品；换箱、改方向/数量/工具、停止/锁回调、失败回滚、隐私/重启及对抗验收仍pending。
