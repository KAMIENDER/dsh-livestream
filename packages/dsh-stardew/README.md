## 接入方式

```text
DSH「大肥鱼·星露谷农场主」预设
    game_start / game_recovery / game_permissions / game_resume / game_continue / game_act / game_stop
                  ↓
StardewRun：固定天数、每日计划、动作预算、换日检查、日报与笔记
                  ↓ MCP stdio
luy-0/StardewValley-MCP
                  ↓ 本机认证连接
SMAPI Mod → 游戏主角

StardewRun → 可选本机 HTTP 扩展 → mods/DshStardew
             查询信息 / 原生 UI 与输入 / 限时钓鱼和近战
             以 saveId 隔离长期记忆与固定预算检查点
```

寻路、原有原子接口与睡眠继续复用 [StardewValley-MCP](https://github.com/luy-0/StardewValley-MCP)。新增动物/机器专用动作在独立扩展内调用游戏原生方法；不修改存档XML、直接设置产物或凭空发放物品。原桥接依据为上游 `9d81eb50270c539bea52b3068029b890ef2243f0` 的公开 V1 契约、工具 Schema 和四个示例 Skill。

本包与 `dsh-game` 是独立的 DSH 游戏预设。只在各自预设中注册同名 `game_*` 工具，不能把两套 agent 子插件同时放进同一个预设。

新增的 [DSHStardew 游戏端扩展](../../mods/DshStardew/README.md) 使用 SMAPI4.5.2 原生输入和当前游戏状态。没有安装它时保留原桥接能力；安装后按明确版本和工具清单开放新增接口，不按工具名前缀自动批准未知工具。

## 准备游戏与桥接

`game_act(action="workflows")` 返回当前源码语义流程与真实参数。`plant` 的 `text` 包含 `seedItemId`（背包的实际 `(O)…` ID）、`positions`（同一当前地点1–8个实际 `{locationId,x,y}`）及可选 `water`（默认true）。它需要扩展的精确cropData种子记录、已有锄头及足量种子/水量；不自动清障、补水或硬编码跳过季节限制。每个变更与直接 `call` 共用每日预算和变更前检查点；结果通过 `tile_completed` 等逐步观察写入本次日志与报告。流程完成只说明当次已列出的后置条件满足，尚未覆盖整个作物生命周期。

1. 安装自己的 Stardew Valley，以及 [SMAPI](https://smapi.io/)。上游桥接当前要求游戏 1.6 与 SMAPI 4.1.0+。
2. 按上游[快速开始](https://github.com/luy-0/StardewValley-MCP/blob/main/docs/getting-started.md)安装配套 Mod 和 Python MCP 程序。需要包含浇水、收获、补水、睡眠四个示例 Skill；本包启动时会核对实际工具列表，缺少时拒绝开始。
3. 通过 SMAPI 启动游戏，进入单人农场主存档，完成当前对话并关闭菜单。建议先使用单独的体验存档。
4. Mod 会生成 `Mods/StardewValleyMCP/config.json`。本包在本机读取其中的连接地址、端口和共享密钥，不把密钥发给模型或保存在插件设置里。

macOS Steam 默认配置位置：

```text
~/Library/Application Support/Steam/steamapps/common/Stardew Valley/Contents/MacOS/Mods/StardewValleyMCP/config.json
```

如果游戏装在其他磁盘，或应用包目录结构不同，使用 DSH 插件设置填写真实配置文件路径。

## 安装 DSH 插件

初次安装时已执行构建；本轮新源码尚未构建。以后安装新版或在其他环境安装时，需要以下步骤：

```bash
pnpm install
pnpm -C packages/dsh-stardew build
```

在 DSH 侧边栏「插件」→「添加插件」中填写 `packages/dsh-stardew` 的绝对路径，启用后重启 DSH。

插件设置：

- `mcpCommand`：已安装的 `stardew-valley-mcp` 可执行文件路径。留空先查 `~/.local/bin/`，再查进程 PATH。这里填程序路径，不是整条 shell 命令。
- `modConfig`：上述 Mod 的 `config.json` 路径。留空尝试 Steam 默认位置，支持 `~/`。
- `captureWindow`：直播时 OBS 的游戏窗口名称。Mac 使用 OBS 列表中完整的窗口标签；Windows 使用 OBS 的 `标题:窗口类:程序`。留空时自行在 OBS 里选择画面。
- `extensionConfig`：可选 `Mods/DSHStardew/config.json`；留空在原 MCP Mod 的相邻目录发现。显式指定却缺失/不兼容时拒绝接管。扩展另需按[说明](../../mods/DshStardew/README.md)构建安装，首次持久控制前正常保存一次农场。

首次使用需要安装本包的 MCP SDK 依赖；仓库依赖锁已随本机安装更新。链接本地插件前先在仓库执行 `pnpm install`，链接本身不会安装这些依赖。

## 单独观看 AI 经营

新建一个 DSH 对话，选择「大肥鱼·星露谷农场主」，发送：

> 接管主角，自己观察农场并安排今天。优先照顾作物，留出体力和回家时间；正常睡眠进入次日后总结并停下。

模型通过 `game_start(game="stardew")` 连接。每个工具的参数通过 `game_act(action="schema", name="工具名")` 取得，再用 `call` 调用；要结束当天用 `end_day`。

新版源码的连续经营示例（构建并重启后才能用）：

> 连续经营 3 天，优先照顾作物，控制游戏金币开支，每天留下经营记录。完成第 3 天正常睡眠后停下。

对应 `game_start(game="stardew", days=3, goal="照顾作物，控制游戏金币开支")`。`days` 必须为 1–28 的整数；省略时是 1。同一会话重复 `game_start` 只返回当前观察，不能改变预算。

| `game_act.action` | 用途 |
| --- | --- |
| `catalog` | 查看玩法与缺口；可用 `name` 选择返回过的分类 ID |
| `schema` / `call` | 查看当前真实参数 / 执行已接入工具 |
| `plan` | 更新当前日计划；旧日报不会被重写 |
| `remember` / `report` | 记录模型待办 / 读取本次日报与笔记；最多 64 条笔记，每条 2000 字符 |
| `memory` | 分页读本存档长期记忆；text JSON 可选 section=summary/tasks/notes/observations、offset、limit(1–20) |
| `task` | text JSON 保存任务文字、优先级1–5、dependsOn、金币/体力估算、dueDay、模型状态 todo/done/blocked；依赖必须存在且无循环 |
| `schedule` | 依当前金币、预留30体力及模型任务依赖筛选；缺估算不默认为零，不是已验证的执行计划 |
| `end_day` | 调用睡眠 Skill，核对当天完成证据 |
| `next_day` | 只在睡眠已确认且仍有天数额度时进入下一天；不会再次调用睡眠 |

睡眠后和 `next_day` 之间允许查询，拒绝所有游戏变更；连续调用 `next_day` 不会重置当日动作数。游戏时钟仍在前进，长时间停留到日期再次变化会停止接管。日报的 `observed` 是游戏返回，`planByModel`、`goalByModel`、`notesByModel` 是模型文字；提交了多少动作不代表成功了多少动作。跨天记录不自动转换为另一存档的记忆。

可选的 [游戏导演](../dsh-game-director/README.md) 可以选择星露谷并创建这个预设的子会话。根插件提供 `stardewControl.stopSession(ownerId)`，让导演取消或结束任务时只释放自己的子会话控制连接。

游戏时间持续流动，AI 思考和解说也会消耗游戏时间。22:00、体力低于30、生命低于20或已提交128次变更后，只允许关闭菜单、撤退/移动返家和睡觉收尾。遇到无法处理的剧情菜单，需要人工接管。

`game_stop` 会取消调用并关闭控制进程，**不会暂停游戏时钟或关闭游戏窗口**。网络取消是否已经中断游戏中的动作要以游戏现场为准；未知结果不能自动重复执行。

## 一份背包食用/饮用（新增源码，未验收）

## 原生制作、烹饪和真实材料来源（仅源码）

`craft_recipe`需要`mode=crafting/cooking`、实际已学`recipeName`及`materialBudget`，默认1次，最多25次。`entry=current`使用已打开页；`backpack`正常打开背包制作页；`station`指定当前地点实际厨房/工作台`position`，先正常导航相邻再交互，原生自己取得材料锁和打开页面。厨房候选排除农舍原生173号冰箱格，避免把储物界面当烹饪页。未知菜单、构建或自定义配方/容器/物品类另需适配。

预算每项是`{sourceKind:"player"|"containers",itemId,quality,maxCount}`，`maxCount`为整批累计上限。`containers`明确允许该原生页面连接的冰箱/小冰箱/工作台材料，建立页面后固定实际容器集合；不能跨地图或任意容器取料。预检只在副本计数上复现本构建玩家优先、各来源倒序、分类及野种替代顺序。齐氏调味料若在真实来源可用，原生会自动使用；必须`allowSeasoning=true`并给相应来源的`(O)917`预留预算，否则在制作前拒绝，不修改原生规则来跳过它。

查询读取实际页面已构建配方，不调用`createItem/GetItemData(false)`预览随机产物。静态证据还显示原生hover会调用`createItem`；此专用处理器按实际组件x/y调用已核对的原生点击路径，不为了点击移动真实鼠标或触发hover预览。原生UI自身和用户操作仍可能推进游戏状态，不能承诺全局RNG冻结。

## 普通商店金币交易（仅源码）

## 错误、日志和恢复

- 标题界面、没有加载存档、多人玩家在线、缺工具或认证失败：不开始接管。
- 日期或主角意外变化：停止后续变更，不当作成功换天。
- 变更结果为 `unknown` 或连接在调用中断开：锁住后续变更，先人工核对现场；不靠重试猜测结果。
- 同一 DSH 进程内只允许一个会话控制游戏，拒绝同时发出两个动作。扩展再用单客户端租约协调其自身操作；不能阻止用户手动操作或独立 MCP 客户端。
- 日志保存于 `$DSH_HOME/dsh-stardew/runs/<runId>.jsonl`（未设置时用 `~/.dsh/`），记录固定预算、计划、模型笔记、提交参数、返回结果和每日完成证据，不记录连接密钥。日志写入失败时会在进度和报告中提示。
- `sessions/` 保存会话与 runId/预算绑定，旧版记录继续有效，重复 `game_start` 不能重新领取预算。
- 有扩展身份时，`farms/<saveId>/memory.json` 保存跨会话笔记/任务/历史观察，`checkpoints/<runId>.json` 保存原预算与进度。
- `game_resume(runId="report返回的UUID")` 显式恢复：先停止旧连接，再核对同一已保存存档、版本、日期和控制摘要，无待确认动作才续接。恢复保留原天数、日报、计划和已提交动作数，不重放动作或恢复旧 UI Ref。客户端崩溃后的旧租约最长等待2分钟过期。
- 重启后没有活动连接时，用独立 `game_recovery` 查询本会话的runId和磁盘检查点。它不接受自报会话ID，不连接游戏，不把磁盘可恢复当作现场一致；旧版无runId的记录仍不能用来重领预算。恢复还核对实际游戏程序集版本及MVID。
- `game_act(action="production", text="{\"offset\":0,\"limit\":8}")`分页读取本存档生产待办。`machine_cycle`首次提供实际位置、机器ID及可选input；不提供input时只接手已观察到的processing/ready周期。续接只传返回的jobId，不能改变原目标、预算或漏斗选项。生产中返回waiting及实际游戏分钟，不自动推进时间；满包或条件拒绝保留待办。
- 生产状态位于`farms/<saveId>/production/<jobId>.json`，完成后移出active索引但保留独立历史。分拆守恒总量，投料/收取前先落盘阶段；loading/collecting/uncertain不能盲目重放。`machine_stop_tracking`只停止跟踪已知记录，机器继续原生产，不退款；它不能清除结果未知的记录。
- 每次变更前先保存 pendingAction。崩溃在发送/确认窗口内，即使动作可能没发出，也拒绝恢复；先核对现场。停止于异常或已完成的任务不能恢复来延长预算。磁盘写入失败时停止变更，不覆盖损坏的历史记忆。

1. 通过 DSH 农场主会话完成连接和目标执行。早期插件加载，以及独立 MCP 客户端的认证、工具发现、主角身份读取、转向和还原已确认。
2. 对明确地块执行一次浇水，并从新查询中确认湿润状态及体力变化。
3. 确认一小块农田的批量操作能正确报告部分完成与失败。
4. 睡眠流程实际到床、确认睡眠、跨日，且不会把昏倒当作成功。
5. 取消、断线、切换存档、并发调用时不会重放未知动作。
6. OBS 捕获、声音和弹幕指令到游戏会话的联动。
7. 多天任务每日正常睡眠；月末、季末、年末换日；中途停止、重复 `next_day` 和重复 `game_start` 不扩大预算。
8. 日报区分实际状态与模型笔记，终止任务不再发进度心跳，旧客户端构建升级后仍保留会话领取记录。
9. 新扩展的钓鱼、近战、各原生界面流程、不同缩放下放置，以及分页信息、记忆隔离、检查点恢复和客户端租约。当前全部未验收，详见[扩展说明](../../mods/DshStardew/README.md)。

扩展实现及未覆盖部分见[开发记录](../../docs/stardew-gameplay.md)。如何将此样例用于其他游戏，见[扩展设计](../../docs/game-adapter-design.md)。

## 已有矿梯、电梯、竖井与返地面（新增源码，未验收）

无匹配现有出口时waiting，已完成跳数分开记录。只有mine_transition_verified才生成去重经历，明确explorationCompleted=false、miningOrKillProven=false，不保留旧地图/菜单实例key作执行引用。没有把已有梯子转层当作无梯找梯、击杀/全武器战斗、采矿、矿山入口大厅/火山、完整晚间/低资源返家或崩溃后持久续接。当前23查询/18控制，仍0.3.0按实际发现启用；新流程和原始控制都须具体主人审核，没有可复用探矿范围。未编译测试、安装、更新客户端、转层/受伤/拾取或创建实际经历/批准，全部新增实机验收pending。

## 固定目标近战批次（源码预览，未验收）

`workflows`新增`melee_engage`，要求当前`dsh_query_mine.combat`给出的真实targetKey/完整类型及expectedDeathAnimationCounter，以及实际武器槽、ID、原生家族，明确1–32个动作、0–4次接近、0–4次特殊招式、观察生命损失和同地点半径。由实际MCP背包Ref装备；逐次使用dsh_melee公开普攻/特殊入口和原生冷却，不能按最近目标或新同名对象换怪，也不能在倒地/复活后默默接受新生命阶段。原生特殊可以多段/范围攻击，不等于只命中一个目标；受击无敌只有限等待，连续两次普攻无观察伤害则waiting重规划。

每次Native前后夹住独立MCP全背包，绑定原地点/装备实例与内容，核对完整数量、金币/生命和当前可操作状态；每个原生游戏tick的观察生命下降与查询间下降累计，不因恢复返额度。接近/装备/等待均不自动接受未批准物品或金币减少。原日pending和提交预算不变，仍预留2次退出动作；预留不保证找到或走到出口。半径在每次查询时核对，导航途中还没有逐帧边界监视或动态避障安全保证。

可给明确同地点`retreatTo`及高于硬生命下限的`retreatAtHealth`。到阈值优先正常导航一次、独立核对准确到达与资源后waiting；并非安全逃脱、全矿返程或生命下限触及后的自动救援。未证明终态的目标不见/非正血量、出圈、预算不足均waiting，已提交输入却无法完整确认则停止接管且不补打。默认objective=actions仍只完成有限动作批次；objective=defeat_target只有同一实例的原生死亡规则和独立资源/库存确认才completed，额度用尽仍在或未知机制均waiting，不偷换成挥满次数成功。

人物经历只接纳已核对动作、明确到达与`melee_target_defeated`的原生终态观察，保留有限资源/生命周期事实，不保存临时执行key或模型推断。特定死亡与伤害/拾取因果、整场/全层已清、安全逃脱分开。新流程及原始工具只走具体主人审核，不能从已有农活范围获得战斗权限。当前23查询/19控制，0.3.0按实际工具发现启用；旧端缺dsh_melee或生命周期字段时不提交本流程变更。本轮没有编译测试、安装/更新客户端、实际挥武器/移动或创建批准/经历；全部新增验收pending，弹弓/弹药、其他未识别生命周期、全怪物战术、完整返家及持久中断续接仍缺。

只读生命周期规则静态依据为本机同SHA/MVID的Monster.deathAnimation、NetEvent0.Fire/Poll/Clear、GameLocation.damageMonster/onMonsterKilled与准确Mummy.takeDamage。普通规则要求同实例deathAnimEvent.Counter恰好+1、非正血量、最终从当前完整角色列表移除及击杀统计增加，且整体收据已确认。木乃伊普通倒地会恢复满血、开始复活倒计时并播放死亡动画；最终死亡分支可不增加死亡动画计数，因此另以准确原生Mummy终态移除规则核对。只读原字段，不触发/轮询/清空事件，不订阅回调或直接调用死亡函数。生命周期计数缺失/下降/回绕、状态替换或不匹配停止，不把旧历史当当前可攻击对象；未识别机制无规则便不确认。
