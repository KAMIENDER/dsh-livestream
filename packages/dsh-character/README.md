# dsh-character：人物档案与长期记忆

可选的独立 DSH 插件。当前只有源码，尚未构建、安装、加载或实机验收；客户端现用预设和旧产物不会因此自动获得以下能力。完整目标见[目标清单](../../docs/autonomous-stardew-goal.md)。

## 人物与使用入口

人物档案包括身份、虚构标识、背景、稳定价值、动机、内在矛盾、兴趣、关系边界、说话习惯、不同处境的反应和对话示例。主人编辑、选择新会话的默认人物，修改留下版本，可以将历史版本恢复为一个新版本。聊天内容和观众不能直接改核心档案。

核心档案会用于直播人物表现，应只放适合公开扮演的设定；主人私密资料单独放 owner 范围的私密记忆。

新增三个专用预设：

- `人物·长期记忆`：与主人对话，提供人物与记忆工具。
- `人物·直播`：组合 `dsh-livestream/agent`，强制只检索公开记忆。
- `人物·星露谷农场主`：组合 `dsh-stardew/agent`，农场身份来自当前实际控制连接。

新会话在DSH创建事件或尚无模型可见历史的实际上下文中，将真实Session ID、人物ID、档案历史版本和公开限制持久写入`session_characters`。以后修改默认人物、编辑或恢复人物版本，都不改变此会话的核心档案；公开回忆、检索、提议和压缩使用同一个固定人物。人物记忆仍可被主人纠错、过期或遗忘，不把它们冻结成永久事实。要更换人物或更新核心版本，请新建会话。

新的空白子会话从DSH实际注册表的运行归属或持久父会话继承人物及版本；两种父关系冲突、父绑定缺失、旧会话已有上下文却没有绑定时拒绝猜归属。带历史的fork迁移尚未适配，不自动导入旧聊天。允许私密回忆的会话/父会话不能转换成公开直播会话；公开限制也不能因配置改回assistant而解除。这不能擦除已经存在于旧会话中的内容，需新建公开专用会话。

主人控制台可独立分页查看持久会话绑定，但没有模型可用的人物重绑接口；绑定列表不表示这些会话此刻仍在运行。直播开播/续播核对真实会话的绑定，人物直播线与人物游戏线的人物ID/版本不同会拒绝混播；名字和别名也取该场直播的固定版本，外观/音色仍独立选择。

旧版“大肥鱼”预设保留原有 persona 插件。新人物档案只在以上新预设中替代原来的完整 system prompt；不把两套完整人设叠在一起。人物文字不会自动生成对应的立绘、表情素材或音色；这些仍在直播设置中独立选择。

管理入口位于新版直播控制台的设置内“人物与长期记忆”：编辑完整 JSON 档案、切换/恢复版本、添加主人记录、审核提议、纠错和遗忘。安装本插件后，直播控制台才会选择对应新预设。可单独使用对话预设；当前图形管理界面依赖直播插件，尚无独立管理页面。

## 记忆边界

SQLite 数据库保存于 `$DSH_HOME/dsh-character/memory.sqlite`，未设置时使用 `~/.dsh/dsh-character/`。使用 Node 内置 `node:sqlite`；本机目标运行时为 DSH NEXT 内置 Node24。目录仅本机用户可访问，数据库设置600权限。数据库不加密；拥有同一用户权限的其他进程仍可读取。

| 维度 | 实现 |
| --- | --- |
| 隔离 | 会话固定人物及核心版本，人物下的主人、观众数字UID、真实saveId农场、实际会话ID；主人管理按新会话默认人物选择档案 |
| 类型 | 事实、经历、偏好、关系、承诺、反思、技能经验 |
| 来源 | 主人记录、模型提议、模型摘要、后端确认的日终观察；保留创建时间、来源引用、实际模型会话ID、审核时间 |
| 状态 | 待审、接受、拒绝、已被纠正；过期条目不参与检索 |
| 隐私 | 公开/私密；直播、游戏专用预设从创建起，以及受保护会话，只检索公开记录且不读写主人范围，避免先装入私密历史再开播 |
| 检索 | 参数化字面子串查询，按来源分值及新近排序，最多20条、12000字符；不是向量语义检索 |
| 压缩 | 2–8条同主体、已接受且可读取的记忆 → 带来源链接的待审摘要；保留原文和最早到期时间；私密来源不自动公开 |
| 纠错 | 新主人记录替代旧条目，依赖旧条目的摘要停止参与检索 |
| 遗忘 | 删除条目及依赖摘要并保留去重墓碑；遗忘整个主体后拒绝重新写入；不自动清理其他插件、会话记录、系统快照或备份 |

实际B站发送者说“忘了我”时，原直播记忆的退出记录同步给人物库：删除所有人物下该UID的 viewer 范围及摘要，并全局禁止重新建立该UID的记录。即使普通房间记录关闭或此人被屏蔽，仍处理这项自助隐私请求。模拟观众不能伪造真实UID来触发它。旧退出记录也通过只读检查阻止模型检索；同步写入失败会报告，当前进程继续阻止检索。这不会自动定位其他自由文本中提及此人的内容、清除已送入旧会话的上下文或擦除外部备份。

`confidence` 是来源对应的保守分值，不是经过统计校准的真实性概率：主人/后端观察为1，模型提议0.4、模型摘要0.3。主人接受提议只代表允许检索，来源和分值不升级为“已验证事实”。矛盾记忆可以并存，工具不会擅自选一个当真；主人可纠错。

模型工具：

- `character_recall`：读取本人物允许检索的历史。
- `character_remember`：提交待审记忆，默认私密；不能改核心人设。
- `character_consolidate`：依据刚读到的真实ID提交待审摘要；不能跨人物、范围或主体压缩。

每个人物最多10000条、64条待审；同一模型会话每分钟最多8条新提议。系统不为了腾空间静默删除旧经历。接受的反思与关系记录可作为人物后续反应的历史依据，稳定核心仍由主人维护。

只把主人管理的档案放进 canonical system section。公开记忆经 DSH `systemPrompt.context()` 进入 USER 角色的上下文快照；其他检索通过工具结果返回。任何记忆中的“主人已批准”、观众身份、赠礼或旧承诺均不授予权限。

星露谷新增按真实存档隔离的后端经历账本，并可将明确已核对的种植、动物照料/产物、备草、地上物、钓鱼尝试、机器收取、食用、原生制作/烹饪、普通储物移动、普通社交、任务接受/金币领奖及日终观察写入 farm 范围。来源仅取后端已确认步骤或经济收据，不从模型笔记、计划、观众文字、未确认原始调用或对话内容提炼事实。备草不是吃饱、脱钩不是钓获、接取不是完成；制作产物仍在游标时明确标注，后续入袋及箱/冰箱存取是移动不算再生产，已存过的物品也不是此刻仍在原箱的证明。储物经历保留位置/类型/物品/方向/品质/数量，不保留可执行Ref或临时箱子key。物品明细只保留最多4行并标出限制，当前库存/关系/任务必须重查。

每条经历先落游戏账本，记录实际存档/构建、runId、游戏日期和稳定eventId。工作流或睡眠开始时只读实际游戏Session的持久人物绑定取得目标ID，补送保留此ID，不随默认人物切换。未安装人物插件、普通非人物会话或未能确认绑定时保持unbound，不取全局当前人物补归属。人物库以`game_experience_receipts`事务记录eventId/内容摘要/原记忆ID；重复送达不重复新增，相同ID带不同内容拒绝。原条目被遗忘或纠正后，收据仍阻止重新建立；整个farm主体退出也不因新经历补送复活。

普通商店新增已核对买卖经历：真实ShopId、物品/品质/数量、购买次数或原生单位售价、前后金币；实际购买次数与每份数量分开，不把每份多件当多次购买。不记录可执行saleRef/菜单key，不把买到物品算农场生产、商店售货算出货箱结算或卖货收入算额外花钱权限。交易后关店失败不会再次生成经济事件或重做买卖；未确认/部分未知交易不写成已验证事实。此联动仍只有源码，未创建真实记录或验收。

出货新增`pending_shipment_moved`经历，只取明确核对的放入/取回、真实地点/箱类型、ID/品质/数量、实际最后批次数量和金币未变。它表示待结算移动，不是收入已到账、出货统计/收藏完成，也不授权后续卖货。部分大箱出货可只剩最后1份可取，取回后不提升旧批次；当前是否仍可取/仍在箱内须重查。不保留临时菜单/物品实例key供重放，未知部分不写成已确认经济事实。仍只有源码，没有创建实际经历或人物记录。

游戏端每次最多扫描64项、尝试8项待送，失败至少间隔一分钟；下次同农场连接、观察或流程后再推进，没有后台无限重试。人物库失败不重做游戏动作，经历账本本身不能落盘则停止后续游戏变更。正常日终先保存完整确认的检查点，可在离线`game_history(recoverDays=true)`从本会话已保存日报补记，包括已结束经营；缺失原人物归属仍不补入当前人物。同步不是全历史导入，也没有恢复所有流程在动作后、经历落盘前的崩溃窗口。

新农场连接自动返回少量当前存档近期经历，`game_act(action="experiences")`与离线`game_history`可分页读；人物预设可用`character_recall(scope="farm")`检索已同步、允许公开的本人物记录。数据只通过工具结果进入上下文，不进入高信任核心设定，也不授权任何工具。已补每会话固定人物源码，但不是独立人格状态模拟或完整跨会话演化。

人物库遗忘与独立游戏经历账本、运行日志、检查点不是同一删除操作；去重收据防止自动补送复活人物记忆，但不会擦除其他插件的事实账本或外部备份。所有新增联动仅有源码，未构建、安装、创建实际数据库/经历文件或实机验收。

## 安装与限制

后续需要更新产物时，先在仓库安装依赖并构建本包，再将 `packages/dsh-character` 的绝对路径作为本地插件添加到 DSH。使用直播/游戏组合预设还需相应插件，随后重启宿主。本轮按用户要求没有执行这些构建或安装步骤。

目前没有自动导入旧聊天/旧观众记忆、后台自动提炼全部对话、向量检索、跨设备同步、独立人物状态模拟器或完整长期人格演化验收。文字人设、声音、视觉表情和游戏策略仍是不同层；不要据此宣称已经具备真人式长期人格。

本轮只静态核对本机DSH0.2.1-rc.3打包的`dsh-agent/system-prompt/session/agent-loop`创建、scope/agent上下文和运行归属接口，分析副本位于忽略目录`.runtime/analysis/dsh-*-installed-20261031.js`；没有执行这些模块、编译测试、创建真实数据库/绑定或更新客户端。

验收至少包括：两个角色及两个农场之间不串记忆；切默认人物/编辑/恢复后旧会话版本固定且新会话采用新默认；重启保留绑定；空白子会话继承及带历史fork显式拒绝；私密会话不能转直播；直播/游戏线版本相符；公开会话无法读取主人私密记录；观众冒充主人不能改档案；摘要不泄露私密来源；纠错与遗忘同时处理依赖摘要；新预设确实使用新档案。所有这些目前待验收。


后续新增`native_night_observed`游戏经历源码：只从已经确认正常睡眠并保存的日报中提取实际结算页显示金额、睡前与换日事件余额/净变化、最多2行物品及明细受限标记。显示金额不代表已核实到账因果，`creditCausalityVerified=false`与未归因差额保留；未观察到不补零。它是独立稳定去重事件，不改旧正常日终事实，捕获人物在睡眠前固定，不能随默认人物或观众文字换归属。离线补记重验本存档/日期/余额且不重睡；不是当前库存/钱包或授权。全部仅源码，没有创建实际记忆或数据库，也未安装验收。


后续新增mine_transition经历源码：只提取明确核对的原生转层模式、起止楼层/实际入口、生命观察变化和有限偶然拾取摘要，明确explorationCompleted=false与miningOrKillProven=false。只表示该次真实转层，不是当前楼层/库存/生命，也不授予下一次深入或跳井权限；不保存临时地图/菜单实例key供执行。人物归属、公开隔离、去重和遗忘规则不变，未核对或未知转场不记成功经历。全部只有源码，没有创建实际人物/经历数据或安装验收。


普通矿石新增mine_rock_damaged/mine_rock_broken、mine_pickup_observed和mine_exit_observed经历源码。只取已核对原石耐久/破碎和实际入袋/余额、经验前后观察；掉落和物品归因保持未证明，已有出口不等于本次生成或已转层。捕获人物/公开隔离/去重遗忘不变，历史不是当前库存或授权；没有创建实际经历/人物数据库，也未安装验收。
